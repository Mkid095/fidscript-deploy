## [Unreleased]

### Fixed
- `fix(auth): forward inviteKeyword from dashboard to /auth/register` — The SDK's `auth.register(email, password, name, authMethod)` dropped `inviteKeyword` before the network call, so the server-side `SIGNUP_INVITE_KEYWORD` check in `auth-register.service.ts` was bypassed for direct API callers (and for dashboard users when `NEXT_PUBLIC_INVITE_HASH` was unset, since the client validation short-circuits). The SDK `register` signature now accepts an optional `inviteKeyword` and forwards it in the body; `registerMethod` (contexts/auth-methods.ts), the `register` wrapper in AuthProvider, the `register` shape in auth-types.ts, and `register-form.tsx` are all updated to pass the field through end-to-end. Files: `packages/sdk/src/modules/auth.ts`, `apps/dashboard/src/contexts/auth-methods.ts`, `apps/dashboard/src/contexts/auth-provider.tsx`, `apps/dashboard/src/contexts/auth-types.ts`, `apps/dashboard/src/app/register/register-form.tsx`.
- `fix(deploy): correct production domain configuration in env vars and Traefik` — Four production-impact bugs that would block a fresh deploy: (1) `CORS_ORIGIN` in `installer/docker/docker-compose.yml` pointed at `https://app.${PLATFORM_DOMAIN}` but the dashboard is hosted at `https://${PLATFORM_DOMAIN}` (root), so browser auth/API calls would be CORS-rejected; fixed to include both origins and updated `apps/api/src/main.ts` to parse a comma-separated origin list and disable credentials when `*` is used. (2) `MINIO_EXTERNAL_ENDPOINT` defaulted to `http://localhost:9000` (meaningless inside a container); default now `https://storage.${PLATFORM_DOMAIN}`. (3) `installer/traefik/dynamic.yml` template had `Host(`storage.fidscript.com`)` (wrong zone — apex instead of the platform subzone) and the acme-challenge backend pointed at `http://127.0.0.1:8080` (the traefik container's own loopback, not stalwart); both fixed to `storage.deploy.fidscript.com` and `http://fidscript_stalwart:8080`. The dashboard-app alias at `app.deploy.fidscript.com` is also wired so the install-wizard-created DNS record actually resolves to a router. (4) `apps/api/src/modules/installation/providers/traefik-proxy.provider.ts` wrote a `dynamic.yml` using a placeholder `certResolver: myresolver` that doesn't exist in `traefik.yml` — Traefik silently ignores the tls block and certificates never issue; fixed to use the real `letsencrypt-dns` resolver and dropped the bogus inline `certificatesResolvers` block (file providers can't redefine resolvers). Files: `installer/docker/docker-compose.yml`, `installer/traefik/dynamic.yml`, `apps/api/src/main.ts`, `apps/api/src/modules/installation/providers/traefik-proxy.provider.ts`.
- `fix(cli): resolve repository project context` — CLI config now honors `.fidscript/project.json` while walking parent directories, so commands without `--project` use the local project ID; `FIDScript_API_URL` also overrides saved config consistently. Files: `apps/cli/src/config/project-context-loader.ts`, `apps/cli/src/config/index.ts`.
